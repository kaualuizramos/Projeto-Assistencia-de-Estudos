# 1.3 Productivity Assistant (AI)

> AI provider: selected through the `ESTUDA_AI_PROVIDER` environment variable (`gemini`, `openai`, or `ollama`). When it is not set, the System uses, in this order, the Gemini key (`GEMINI_API_KEY`), the OpenAI key (`OPENAI_API_KEY`), a local Ollama (`OLLAMA_HOST` defined or Ollama detected on `http://localhost:11434`), and otherwise Gemini, which is then unavailable until a key is configured. See ADR 0001 and ADR 0005.

- **RF13:** The System SHALL allow the user to start a conversation with the productivity assistant.
- **RF14:** WHEN the user sends a message (1 to 8000 characters) through the chat, the System SHALL send the message and its conversation context to the AI service, through the AI integration component, after removing the user's registered name and e-mail address, any other e-mail address detected in the text, and credentials written in common formats (for example "senha: ...", "api key = ..."). The removal is pattern-based and does not guarantee that all personal information typed by the user is removed.
- **RF15:** WHEN the AI service returns a response, the System SHALL display the response in the current conversation.
- **RF16:** IF the AI service fails or returns an invalid response, THEN the System SHALL inform the user that the AI service is unavailable (indicating the reason when known, such as missing provider configuration), keep the user's message in the conversation with status "Failed", and allow the user to resend it.
- **RF17:** WHEN a message is sent in a conversation, the System SHALL include the 20 most recent messages of that conversation as context in the request to the AI service, excluding earlier messages with status "Failed".
- **RF18:** The System SHALL store the user's conversation history associated with their account, allowing several conversations per account and the selection of any of them.
- **RF19:** WHEN the user describes a complex task to the assistant, the System SHALL request from the AI service a structured response with up to 5 suggested subtasks, each with a title of up to 120 characters, and SHALL validate it against the expected schema before presenting it; an invalid response is handled as a failure per RF16. A message is treated as a complex task when the user selects the option to generate steps or when the text contains one of the cues "dividir", "complexo", "complexa", "trabalho", "projeto", "apresentação", "relatório", "etapas", or "planejar".
- **RF20:** WHEN the user requests help starting a task, the System SHALL allow the assistant to suggest a concrete next action; the assistant is instructed, through its system prompt, to answer in Portuguese and to help the student choose concrete next steps.
- **RF21:** The System SHALL present each suggested subtask as a proposal and SHALL add it as a subtask of the pending task selected by the user only after the user accepts it, optionally after editing its title; rejected proposals are never added.
- **RF42:** IF the AI assistant is disabled or the user has reached the daily message limit (counted as assistant responses delivered during the current UTC day), THEN the System SHALL reject new chat messages without storing them, return the typed text to the input field, and inform the user, keeping all other functionality available.
