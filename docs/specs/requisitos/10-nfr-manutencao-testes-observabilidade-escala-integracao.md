# Non-Functional Requirements — Maintainability, Testability, Observability, Scalability and Integration

- **RNF121:** The System SHALL be organized into five service modules in the `estuda` package (Authentication, Tasks, AI Chat, Focus Sessions, Notifications), each with its own business logic and data access, interacting with the others through their public service interfaces; the desktop interface (`estuda/ui.py`) calls these services and has no routes. See ADR 0003.
  - Known deviations: the Focus Sessions and Tasks modules insert notifications directly into the notifications table instead of calling the Notifications module, and the History screen queries the database directly.
- **RNF122:** The System SHALL provide automated tests for all critical business operations, written with `unittest` against an in-memory database and simulated AI and e-mail integrations, without network access or credentials (`python -m unittest discover -s tests`). The interface itself is verified manually. See ADR 0008.
- **RNF123:** The System SHALL record application errors and relevant system events in the `estuda.log` file and on the console, without storing passwords, authentication tokens, API keys, or chat content in logs.
- **RNF125 (not applicable to the desktop version):** The application serves one local user at a time and has no server. Original requirement: "The System SHALL support at least 100 concurrent authenticated users while maintaining the performance requirement defined in RNF101."
- **RNF126:** The System SHALL isolate communication with each external service behind a dedicated integration component, so that the rest of the System depends only on its interface: the AI providers (Gemini, OpenAI, and Ollama) implement a common `AIClient` contract in `estuda/integrations/ai.py` and are created by a factory from environment variables, and e-mail delivery is performed by the SMTP component in `estuda/integrations/email.py`. See ADR 0005.
  - Known deviation: the chat service and the interface identify the provider by its class name to choose messages and labels.
