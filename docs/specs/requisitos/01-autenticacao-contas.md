# 1.1 Authentication & Account Management

> Platform: local desktop application (PySide6). "Screen" replaces "page" and "service operation" replaces "endpoint". Accounts and data are stored in a local SQLite database on the user's computer.

- **RF01:** The System SHALL allow a visitor to create a Student account by providing a name (up to 100 characters), an e-mail address not yet registered (valid format, up to 254 characters), and a password of 8 to 1024 characters.
- **RF02:** WHEN a user submits an e-mail address and password that match a registered account, the System SHALL authenticate the user and open an authenticated session in the application that expires after 8 hours without mouse or keyboard activity, requiring the user to sign in again.
- **RF03:** IF the authentication credentials are invalid, THEN the System SHALL deny access and display a generic error message ("E-mail ou senha inválidos") that does not reveal whether the e-mail address is registered; the same message SHALL be displayed while the account is temporarily locked by rate limiting (RNF108).
- **RF04:** The System MUST NOT allow an unauthenticated user to access any screen other than the authentication screen (login, registration, and password-recovery request), and SHALL keep the user on that screen until a successful sign-in.
- **RF34:** WHEN a user requests password recovery, the System SHALL send to the informed e-mail address, through the e-mail integration component, a single-use link, valid for 1 hour, that allows defining a new password (8 to 1024 characters), and SHALL give the same response whether or not the address is registered. The link is served on the loopback address (127.0.0.1, random port) by the running application, which then asks for the new password; therefore SMTP MUST be configured and the application MUST be open on the same computer when the link is used.
- **RF35:** WHEN the user requests account deletion, the System SHALL require confirmation (confirmation dialog) before deleting the account.
- **RF36:** IF the user confirms account deletion, THEN the System SHALL permanently delete the account and all its tasks, subtasks, reminders, notifications, conversations, messages, suggestions, focus sessions, and password-recovery tokens, without anonymization.
- **RF37:** The System MUST NOT allow a user, including one with the Administrator profile, to access, modify, or delete another user's tasks, subtasks, reminders, notifications, conversations, messages, or focus sessions.
- **RF40:** WHEN the user requests logout, the System SHALL terminate the authenticated session and return to the authentication screen.
- **RF41:** The System SHALL allow a user with the Administrator profile to enable or disable the AI assistant and to define the maximum number of assistant messages per user per day (1 to 500; default 20). The Administrator profile is granted to the account registered with the e-mail address defined in the `ESTUDA_ADMIN_EMAIL` environment variable; every other account has the Student profile.
